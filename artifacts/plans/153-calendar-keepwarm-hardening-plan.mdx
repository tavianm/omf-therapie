## Summary

Correctif du path token (`getPersistedOAuthClient` : classement d'erreur, suppression du bootstrap env), session OAuth injectée avec porte de marge (> 5 min) et CAS `updated_at` sur les persists de refresh, remplacement du fan-out ×4 par un batch mono-snapshot, écritures cache strictement vérifiées, et conversion des erreurs response-level Freebusy en throw typé — fermant l'empoisonnement vide sur les deux writers.

## Architecture

**Data flow (après)** :

1. `keepTokenWarm(env)` (cron) — 1 lecture `google_oauth_tokens` (avec `updated_at`) → classée `ok` (client authentifié : valide / rafraîchi avec persist CAS / fall-through `setCredentials` gated à > 5 min de marge) | `transient` (échec select, échec refresh avec marge ≤ 5 min, expiry absent) | `auth-broken` (déinitif). Retourne `KeepwarmSession`.
2. `loadAvailabilitySnapshot(oauth2Client, start, end)` (`google-calendar.ts`) — 1 lecture `manual_time_slots` + 1 Freebusy via la session injectée → `AvailabilitySnapshot` ; mock → zéro I/O ; échecs → erreurs typées (stage partagé).
3. Dérivation pure ×4 — `generateSlotsForRange` + `filterSlotsByBusy` (exporté, déduplique les 3 copies) par `{mode} × {duration}`.
4. `setCachedAvailability(key, slots, ttl)` → `CacheWriteResult` ; init Blobs échouée = `failed`, promise mémoïsé réinitialisé.
5. Chemin patient inchangé hors : `getAvailableSlots` throw typé sur `calendars[id].errors` (→ 503, jamais d'écriture vide) ; persists de refresh CASés (cron + `getPersistedOAuthClient`).
